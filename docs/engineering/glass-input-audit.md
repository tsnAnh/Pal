# Glass input audit (unit glass-input-single-surface)

Scope: every text input under `apps/ios` (App and Packages), Mac, iPhone and iPad. Line numbers are the line on main `afa68d67` before the change. Decisions "yes/no" for the double surface come from reading the style and the container; none was reproduced on a device (the cloud has no Mac or Xcode).

## Root cause

`FloatingSearchBar` (the "Search skills" field of `SkillsCatalogSheet.swift:122`) declared `TextField("", text: $text, prompt: ...)` at `Packages/PalDesign/Sources/PalDesign/Components/FloatingSearchBar.swift:86` with no `.textFieldStyle`. Without one, SwiftUI applies `TextFieldStyle.automatic`, the platform default: on macOS that is a bordered text field with its own bezel and fill (Apple, SwiftUI `TextFieldStyle.automatic`; `PlainTextFieldStyle` / `.plain` is "a text field style with no decoration"). The field sat inside `.palGlass(Capsule())`, so the owner saw the glass capsule holding a second grey rounded field. `ClearGlassSearchField` already had `.plain`, so it was not the source; the call sites of 14+ other fields repeated the same omission (see the table: "own bezel"). iOS defaults to a plain field outside a Form, so iPhone showed no bezel.

Fix at the shared level: `Packages/PalDesign/Sources/PalDesign/Components/PalTextInput.swift`.

- `PalTextField`: the only `TextField`/`SecureField`. `.textFieldStyle(.plain)`, `.focusEffectDisabled()`, prompt in `PalTokens.textTertiary`, secure and vertical-axis variants, Dynamic Type through the caller's font or `PalGlassTextField`'s `@ScaledMetric`.
- `PalTextEditor`: the only `TextEditor`, clear background.
- `PalGlassTextField`: clear glass capsule (`palClearGlass`) around a `PalTextField`, optional `PalIcon`; focus shows as the glass turning interactive (no stroke, ring or border). `ClearGlassSearchField` is built on it.
- Plain SwiftUI is enough on macOS (`.plain` removes the bezel): no `NSViewRepresentable` was added.

## Only the owner can check on a Mac

Each migrated screen shows one glass surface (Skills search, Connect Apps search, Palette, Find in Chat, Vault search, every sheet field); the focus change of the glass capsule is visible with the keyboard (Tab into the field: the capsule brightens; this is the one behaviour not provable without a device); text selection, paste and Return/Escape work; VoiceOver reads the label; the secret fields mask. `UITests/GlassInputE2ETests.swift` takes screenshots of the four screens (CI cannot run UI tests).
